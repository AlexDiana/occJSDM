# occJSDM assistant pilot

This optional folder contains the occJSDM assistant pilot and its Paper2MCP conversion workspace. The four tools are `validate_data`, `fit_model`, `diagnostics` and `summarise_fit`. The server entry point is `paper2agent/src/occJSDM_mcp.py`; its R dispatcher calls the existing package. The local pilot passed independent verification and real stdio acceptance. The tools have also been tested in Posit Cloud; the [Cloud evidence record](paper2agent/reports/cloud-pilot.json) distinguishes user-reported checks from locally inspected artifacts.

Paper2Agent is installed on the local build host at revision `8c2d059165ef8cdcb70dbea76655b9c2b55b38e6`. The scientific source is pinned to `b7b7001e56cea8e3931b09c917ea0e29e6cef3c6`, which predates the current beta release. Setup and reference gates passed: 107 native comparisons, including different model types, row identities and settings. The original independent suite passed 37 tests and reran 18 saved native reference cases with exact comparisons of complete fits and tables. All 19 stdio acceptance cases passed in both development and fresh Python/R runtimes. The separate Mac R restore used recorded dependency archives and rebuilt occJSDM from retained source. The Cloud checks used Linux, R 4.6.1 and Python 3.12.11, with successful source restoration, complete native CSV agreement and an exact same-settings fit comparison. These results establish execution on the recorded runtimes; statistical calibration and changes to the pinned scientific source require separate verification.

Use [the server setup and usage guide](paper2agent/USAGE.md) for the tools, artifact locations, native runtime and Cloud handoff. The source archive, environments and generated references are local ignored build payloads; copying only tracked server files does not install the native package. The [rehearsal review](paper2agent/reports/comparison-review.md) records ten execution scenarios and five teaching exchanges for each of DeepSeek with direct R, DeepSeek with MCP and Sonnet with direct R. These are single unscored rehearsals; a controlled comparison and workshop adoption remain pending. The earlier direct-R smoke test is retained in [its evidence record](paper2agent/reports/cloud-smoke-test.json).

Start with [the model trial guide](paper2agent/class/model-trial.md). It defines the same student tasks for an inexpensive model using R directly, that model using MCP, and a more capable model using R directly. [The teaching instructions](paper2agent/class/assistant-instructions.md) are a draft for the trial, not evidence that Assistant has loaded them.

[The installation script](paper2agent/tests/data/install-reference.R) installs this checkout into a separate R library and records source and installed-package hashes. [The R preparation script](paper2agent/tests/data/prepare-trial.R) checks that provenance, then uses the existing package and test-fixture simulator to create synthetic trial inputs and native R reference results. Both require `jsonlite` and `digest` for their manifests. R package dependencies are still declared in the package's existing `DESCRIPTION`.

The starter fits use only 20 burn-in and 20 kept iterations. They test execution and recognition of inadequate diagnostics, not reliable ecological inference or workshop readiness. Keep generated outputs out of Git. Upload only the generated `student-project/` to a fresh Cloud trial project. That export contains the package sources, quickstart, draft teaching instructions and synthetic inputs, with an explicit file manifest. The full repository contains scoring notes and should stay outside the trial project, along with `grader/`.

The Cloud checks were run in a browser and shared non-sensitive results. Local preparation does not need account credentials. His evidence includes installation, all four MCP operations, native agreement and resource measurements for a short fit and a 5000/5000 schedule. The longer fit completed within the server deadline, but 26 of 130 selected coefficient rows failed at least one convergence screen. It does not establish an inference-ready workshop preset. Detailed provider metadata, a controlled comparison, scientific and Indonesian teaching review, and the student/non-AI workflow still require review before classroom adoption.

Users must learn occJSDM from the vignettes and lessons. Assistants can help navigate the material and execute supported operations; neither Sonnet nor DeepSeek is an authoritative teacher. The observed validation, provenance and native readback support including MCP as an optional execution interface for new users and in the paper.

The approved [implementation plan](../dev/superpowers/plans/2026-10-05-occjsdm-paper2agent-mcp.md) and [class pilot spec](../dev/superpowers/specs/2026-10-04-occjsdm-mcp-class-pilot-design.md) describe the implementation and adoption gate. Ordinary occJSDM installation does not require this folder.
